# 2026-11-08: hex / unhex

- New ops `hex` (one file -> xxd-format dump, `.hex`) and `unhex` (.hex/.xxd,
  or any file whose first line looks like an xxd or hexdump -C dump), on
  `lib/hex.js`, in the `encode` group.
  - The encoder matches the default `xxd` output byte for byte.
  - The decoder reads xxd dumps (any `-c`/`-g`, `-u`, offset jumps filled
    with zeros), `hexdump -C` (including `*` lines) and the site viewer's
    Hex mode, and plain hex (`xxd -p`). `od` / plain `hexdump` output and
    Intel HEX are rejected with a clear message rather than misread.
- `lib/magic.js`: `sniffFile` returns `hex` for xxd / hexdump -C dumps;
  new `decodedName(fileName, exts, type)` shared by unbase64 and unhex
  (`unbase64Name` now wraps it).
- Tests: fixtures from the real `xxd`, `xxd -p`, `xxd -u -c 8 -g 1`,
  `hexdump -C` (with repeated lines) and `od -x`; 7-byte/5-byte/3-byte
  chunking, round trip, offset gap, error messages with line numbers,
  sniffing, pickOp routing, both op mounts. 300 tests pass.
