# 2026-11-08: ar / unar

- New ops `unar` (.a, .ar, .deb, or anything starting `!<arch>\n`) and `ar`
  (files -> .a, GNU format like `ar rc`), on `lib/ar.js`.
  - Reader: GNU/SysV (`name/`, `//` long-name table, `/123` references, `/`
    and `/SYM64/` symbol tables), BSD/macOS (`#1/N` names in the data,
    NUL-padded; `__.SYMDEF…` tables) and plain space-padded names (dpkg).
    Symbol tables and other `/…` special members are skipped, not listed; the
    status line says the flavor and whether there was a symbol table. Thin
    archives are rejected. Random access with `Blob.slice`, headers read
    ahead in 64 KB windows.
  - Writer: basenames only (ar has no folders); two files with the same name
    are an error. Names over 15 bytes go in a `//` table. uid/gid 0, mode
    644, the file's mtime, no symbol table. 10 GB size limit per member.
- `core/pack.js` `packOp`: `option` is optional now (ar has no checkbox).
- `lib/magic.js`: `a` (`!<arch>\n`) and `deb` (`!<arch>\ndebian-binary`);
  `unar` takes both by content.
- A .deb opens in unar; its `data.tar.gz` can be saved and dropped into untar.
  `data.tar.xz` / `.zst` need the Tier 2 decoders.
- Tests: GNU `ar rc` fixture (+ a hand-added `/` symbol table, corrupt and
  cut-off copies), a hand-built BSD/macOS archive with `__.SYMDEF SORTED`,
  a `dpkg-deb -Zgzip` package (data.tar.gz read with readTar), thin archive,
  routing, both op mounts. The browser's own .a is checked with `ar t` /
  `ar p`, and a repacked .deb with `dpkg-deb -c` / `-f`.
