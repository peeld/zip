# 2026-11-08: tar / untar, shared archive UI, content routing

- New ops `untar` (.tar, .tar.gz, .tgz) and `tar` (files/folders -> .tar, or
  .tar.gz with the "gzip" box, ticked by default), on `lib/tar.js`.
  - Reader: ustar, pax (`x` and global `g`: path, linkpath, size, mtime) and
    GNU long names (`L`/`K`), base-256 numbers, header checksums (unsigned or
    signed). A plain .tar is listed with `Blob.slice` in 64 KB read-ahead
    windows; a .tar.gz is decompressed once to list, again up to an entry to
    view/save it, and once in all for "Extract all" (`tarWalk`).
  - Symlinks and hard links are listed (`name -> target`) but not extracted;
    devices/fifos are skipped. Folder names lose their trailing `/`.
  - Writer: parent-folder entries first (like `tar -cf`), mode 644/755, the
    file's mtime, pax headers for names that don't fit ustar's 155+100 bytes
    or aren't ASCII, and for sizes of 8 GB or more. Padded to 10 KB records.
- `core/archive.js` `archiveOp`: the list / view / save / extract-all UI, taken
  out of `ops/unzip`. Readers give `{ entries, open, peek?, each?, note? }`.
- `core/pack.js` `packOp`: the file-list + name + option + create UI, shared
  by `zip` and `tar`.
- Routing by content: registry `input.sniff`, `lib/magic.js` `sniffFile`
  (looks inside a gzip for a tar: `tar.gz`). The shell sniffs a single
  dropped file (magic.js loads on the first drop). A recognised type decides;
  the name is the fallback. `.tar.gz`/`.tgz` now go to `untar`; `gunzip`
  still takes them while it's running.
- Tests: Python tarfile ustar / GNU / pax / pax.tar.gz and GNU `tar -czf`
  fixtures (folder, symlink, 240-byte name), corrupt header, cut-off and
  non-tar input, the browser's own .tar and .tar.gz checked with tarfile and
  `tar -t`, a 9 GB size header, paxRecord lengths, sniffing and routing,
  unzip/untar/tar op mounts.
