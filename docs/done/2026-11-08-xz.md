# 2026-11-08: unxz (.xz, .lzma), .tar.xz / .cpio.xz / .deb data.tar.xz

- New op `unxz` (group `compress`): .xz, .txz, legacy .lzma / .tlz. Inspect
  reads the index from the end of the file (check type, streams, blocks,
  uncompressed size) and decompresses the first 512 bytes to name the output.
- `lib/lzma.js`: our own LZMA decoder (range decoder, LZMA1 + LZMA2 chunks,
  `.lzma` header), written from xz-embedded / the LZMA SDK's description of
  the format. Meant for un7z later.
- `lib/xz.js`: the container (multi-stream with padding, blocks, index and
  footer checks), CRC32 / CRC64 / SHA-256 checks, delta and x86 BCJ filters;
  other BCJ filters are refused by name. `xzInfo` reads the structure without
  decompressing.
- `lib/decompress.js`: `compression(blob)` -> 'gzip' / 'xz' / null and
  `decompress(blob, kind)`; tar and cpio use it, so untar opens .tar.xz and
  uncpio .cpio.xz. `compressed` from readTar / readCpio is now that kind
  (`true` still means gzip). xz.js loads only when an xz is opened.
  Fixed on the way: `openCpioEntry` always used gzip for compressed cpios.
- `lib/magic.js` `sniffFile`: `tar.xz` / `cpio.xz` (looks inside the xz),
  `lzma` (cheap header check, then `isLzmaAlone` from lzma.js).
- About 15 MB/s of output in headless Firefox.
- Tests: Python lzma + `xz` fixtures (presets 0/6/9e, stored chunks, every
  check, odd lc/lp/pb, x86, delta, two streams, 5 blocks, .lzma with and
  without a size), .tar.xz, .cpio.xz, `dpkg-deb -Zxz`, damaged copies,
  sniffing, routing and the op. 564 tests pass.
