# 2026-11-08: hash (checksums), faster CRC-32

- New op `hash` (group `check`, heading "checksums"): drop any files, tick
  algorithms (CRC-32, MD5, SHA-1, SHA-256 (default), SHA-384, SHA-512),
  `[ Hash ]`. Shows each file's hashes and lets you `[ Save list… ]` /
  `[ Copy ]` them in `sha256sum` format.
  - Checking: paste a hash into "Expected" (spaces/colons ignored; the
    length picks the algorithm and ticks its box) -> `match` / `no match`.
    Or drop a checksum list (SHA256SUMS, *.sha256, *.md5, *.sfv, CHECKSUMS, …)
    with the files -> `OK` / `FAILED` per file (by path, else by unique file
    name), and how many listed files weren't added.
  - `[ Stop ]` stops between chunks. Only missing hashes are computed when
    more boxes are ticked later.
- `lib/hash.js`: streaming pure-JS hashers, one pass for all algorithms
  (`hashStream`); SHA-2 constants computed exactly with BigInt roots of
  primes. `parseSums` / `formatSums` read and write GNU (`hash  name`, `*`
  binary, `\` name escapes), tagged (`SHA256 (name) = hash`, also
  `SHA2-256`) and SFV lists.
- `lib/crc32.js`: CRC-32 moved out of `lib/zip.js`, now slicing-by-8
  (Firefox: 115 -> ~670 MB/s). zip and hash both use it.
- Tests: every length 0..300 against hashlib/zlib for all six algorithms,
  all sources in odd chunk sizes, lists made by `sha256sum`, `md5sum --tag`,
  `sha1sum -b`, escaped names and hand-made SFV; lists we write pass
  `sha256sum -c`, `md5sum -c`, `sha512sum -c` (escaped names too); the op
  end to end (list OK/FAILED, pasted MD5). 333 tests pass.
- Speed in headless Firefox (MB/s): CRC-32 ~670, MD5 ~300, SHA-1 ~210,
  SHA-256 ~160, SHA-384/512 ~65.
