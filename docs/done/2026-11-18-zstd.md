# 2026-11-18: unzstd (.zst), .tar.zst / .cpio.zst / .deb data.tar.zst

- New op `unzstd` (group `compress`): .zst, .zstd, .tzst. Inspect walks the
  frame and block headers (frames, content size, checksum) and decompresses
  the first 512 bytes to name the output.
- `lib/zstd.js`: our own decoder from RFC 8878. Frames end to end,
  skippable frames, raw / RLE / compressed blocks, Huffman literals (1 or 4
  streams, treeless reuse), FSE sequences in all four modes, repeat offsets,
  XXH64 content checksum and content size verified. Dictionaries and windows
  over 1 GB are refused by name. `zstdInfo` reads the structure without
  decompressing.
- `lib/decompress.js`: `'zstd'`, so untar opens .tar.zst (and a .deb's
  `data.tar.zst`) and uncpio .cpio.zst. zstd.js loads only when a zstd is
  opened. `lib/magic.js`: `tar.zst` / `cpio.zst` (looks inside), and the
  skippable-frame magic as `zst`.
- Speed: ~35 MB/s of output in headless Firefox, ~70 MB/s in Node (writing
  the sequence bit reader out inline and the XXH64 lane by hand roughly
  doubled each). unxz is ~15 MB/s.
- Fuzzed with single bit flips against `zstd -d` 1.4.8 (800 cases): the
  output never differs from zstd's; 8 damaged Huffman streams zstd accepts
  are reported corrupt here.
- Tests: `zstd` CLI fixtures (levels, --long, --no-check, small window,
  pipe, raw, empty, multi-frame, skippable, XXH64 tail lengths), .tar.zst,
  .cpio.zst, `dpkg-deb -Zzstd`, damaged copies, a dictionary and a 2 GB
  window by hand, sniffing, routing and the op. CI installs `zstd`.
  615 tests pass.
