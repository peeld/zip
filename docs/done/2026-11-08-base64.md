# 2026-11-08: base64 / unbase64

- New ops `base64` (one file -> .b64) and `unbase64` (.b64/.base64 -> file),
  on `lib/base64.js` (streaming TransformStreams, no DOM). New help group
  `encode` ("encoding").
  - The encoder writes 76-column lines with a final newline, byte for byte
    the same as GNU `base64` / Python `base64.encodebytes`.
  - The decoder takes standard and URL-safe alphabets, ignores whitespace,
    doesn't need padding, accepts concatenated padded inputs, and skips a
    leading `data:…;base64,` prefix (even when split across chunks).
    Errors name the byte offset: `not base64: unexpected '<' at byte 0`.
  - unbase64 decodes the first 64 KB when the file is dropped, so a non-base64
    file is rejected before saving. The output name strips `.b64`; otherwise
    the extension comes from the decoded bytes (`lib/magic.js` `sniffType`)
    or the data: URL's mime type (`image.txt` holding a PNG -> `image.png`).
- `lib/magic.js`: magic-number table (png, jpg, gif, webp, pdf, zip, gz, bz2,
  xz, 7z, rar, zst, tar, wasm, mp3, ogg, flac, wav, mp4). Ready for the
  `sniff` routing in `docs/todo/new-ops.md`.
- Not used: `Uint8Array.prototype.toBase64`/`fromBase64`. The table code is
  simple, and one code path means the tests cover every browser.
- Tests: Python-made fixtures (wrapped, `-w0`, base64url unpadded, data: URL,
  concatenated, not base64), fed in 1–7 byte chunks to cross every boundary.
  RFC 4648 vectors, error offsets, naming, sniffing, pickOp routing for .b64,
  both op mounts.
