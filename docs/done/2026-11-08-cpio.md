# 2026-11-08: cpio / uncpio

- New ops `uncpio` (.cpio, .cpio.gz, .cpgz, or anything starting `070701` /
  `070702` / `070707`, plain or gzipped) and `cpio` (files and folders ->
  newc .cpio, or .cpio.gz with the checkbox), on `lib/cpio.js`.
  - Reader: newc, newc+crc, odc, old binary (both byte orders); several
    archives end to end; trailing non-cpio data reported. Hard links (newc
    data-once), symlinks, devices/FIFOs listed but not extracted.
  - Writer: newc like `find . | cpio -o -H newc`; parent folders first,
    padded to 512 bytes, 4 GB per file.
- `lib/source.js`: tar's Blob / stream byte sources and `toStream` moved out
  of `lib/tar.js` so cpio shares them. `streamReader.read` now returns a short
  read at the end of the data (like the Blob one) instead of throwing.
- `core/archive.js`: entries can have `special` ('fifo', 'char device', …):
  listed muted, counted as "devices/FIFOs (not extracted)", never saved.
  untar now sets it for tar device and FIFO entries (they used to show
  view/save buttons for an empty file).
- `lib/magic.js`: `cpio` type and `cpio.gz` from `sniffFile`; gunzip also
  takes `cpio.gz` while running.
- CI installs `cpio`.
- Tests: GNU cpio in newc/crc/odc/bin, a gzipped one, one with a hard link,
  symlink and FIFO (newc and odc), two archives end to end, gzip data after
  the trailer, corrupt and cut-off copies, routing and both op mounts. The
  browser's .cpio and .cpio.gz are extracted with `cpio -idm` and compared.
