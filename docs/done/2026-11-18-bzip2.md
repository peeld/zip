# 2026-11-18: bunzip2 (.bz2), .tar.bz2 / .cpio.bz2, 7z BZip2

- New op `bunzip2` (group `compress`): .bz2, .bzip2, .tbz, .tbz2, .tb2.
  Inspect reads the block size from the header and decompresses the first
  512 bytes to name the output (bzip2 stores no size).
- `lib/bzip2.js`: our own decoder, with bzip2 1.0.8's sources as the
  reference and the same checks. Several streams end to end, zero padding
  after the end, block and stream CRCs (MSB-first CRC-32) verified.
  Randomised blocks (bzip2 0.9.x) are refused by name. `bunzip2Chunks`
  takes any byte source, for 7z.
- `lib/decompress.js`: `'bzip2'`, so untar opens .tar.bz2 and uncpio
  .cpio.bz2. `lib/magic.js`: `bz2` now needs the block size digit after
  `BZh`, and `tar.bz2` / `cpio.bz2` look inside. `lib/7z.js`: the BZip2
  method (`040202`).
- Speed: ~17 MB/s of output in headless Firefox, ~27 MB/s in Node.
- Fuzzed with single bit flips against `bzip2 -d` 1.0.8 (~1400 cases): the
  output never differs; the one case bzip2 accepts and we refuse set the
  randomised bit.
- Tests: `bzip2` CLI fixtures (-9, -1 with 32 blocks, random, empty, one
  byte, runs, PNG, two streams, padding, .tar.bz2, .cpio.bz2), damaged
  copies (flipped byte, cut off, block CRC, stream CRC, junk, randomised),
  7z BZip2 from libarchive and 7-Zip, sniffing, routing and the op. CI
  installs `bzip2`. 697 tests pass.
