# 2026-11-08: brotli / unbrotli (native), zstd check

- Checked native support in Firefox 153: `CompressionStream` and
  `DecompressionStream` take `'brotli'` (not `'br'`); `'zstd'`, `'xz'` and
  `'bzip2'` throw. Chrome and Safari weren't available to check.
- New ops `brotli` (one file -> .br) and `unbrotli` (.br -> file), group
  `compress`, on `lib/brotli.js` (`canBrotli` / `canUnbrotli` feature checks).
  No JS fallback: browsers without native brotli get a clear error.
  - unbrotli decompresses the first 512 bytes when the file arrives (brotli
    has no magic number), so junk is rejected early and the output is named
    from the content. By name only for routing (`.br`).
  - The native decoder catches cut-off input and junk after the end; the
    bare TypeError is replaced with "corrupt or cut-off brotli data".
- Tests: fixtures from the Python `brotli` module; written .br checked by
  Python. Checks that can't run (no native brotli, no module) are logged as
  `SKIP` and counted separately. CI installs `brotli` with pip.
- zstd isn't native, so `unzstd` stays a Tier 2 item to write (see
  `docs/todo/new-ops.md`).
